# 使用示例

> 以下为完整对话示例。为便于阅读，MCP 调用以 `⟨tool⟩` 形式标注。
> 示例中的菜单、券与门店信息为**示意**，实际使用时可售品类、价格与券状态均以麦当劳官方渠道实时结果为准。

## 场景一 · 办公室下午茶拼单（到店自取）

**你**：办公室 4 个人拼个麦当劳，我在珠江新城，到店自取

**拼单官**：

<details><summary>中间调用</summary>

`⟨now-time-info⟩` → 2026-10-11 15:20 周六（下午茶档）
`⟨query-nearby-stores⟩`（珠江新城）→ 命中最近门店
`⟨query-meals⟩`（该门店）→ 返回在售餐品分类与价格

</details>

这是门店可点清单，你直接转发到群里收集需求：

| 分类 | 起售价 | 热门 |
|---|---|---|
| 汉堡 | ¥13.50 | 板烧鸡腿堡 / 麦辣鸡腿堡 / 巨无霸 |
| 小食 | ¥7.00 | 薯条（中）/ 麦乐鸡 5 块 / 麦辣鸡翅 2 块 |
| 饮料 | ¥9.90 | 中杯冰美式 / 中杯可乐 / 橙汁 |
| 甜品 | ¥5.00 | 原味甜筒 / 奥利奥麦旋风 |

> 提示：本店 15:00–17:00 是下午茶档，部分小食有第二份半价。

---

**你**：点完了——小美 14 块、阿强 16、老王 19、我 12，加起来 61

**拼单官**：

先领一下当前所有可领的券可以吗？这一步会往你麦当劳账户里领券，不影响别的。

**你**：领

<details><summary>中间调用</summary>

`⟨auto-bind-coupons⟩` → 新领到 3 张券
`⟨query-my-coupons⟩` + `⟨query-store-coupons⟩` → 汇总可用券池
`⟨campaign-calendar⟩` → 当日活动
`⟨calculate-price⟩` × 3 → 逐组实算（**返回值单位为「分」**）

</details>

可用券池：

| 券 | 面额 | 门槛 | 适用 |
|---|---|---|---|
| 麦旋风任选 | ¥9.90 | 无 | 甜品 |
| 薯薯任选 | ¥9.90 | 无 | 小食 |

三档试算结果（原价 ¥61.00）：

| 方案 | 内容 | 实付 | 立省 |
|---|---|---:|---:|
| A 原始清单 | 大家点的照点，用 3 张 9.9 券 | ¥35.10 | ¥25.90 |
| **B 凑单过门槛** ✅ | 加 1 个原味甜筒（¥5.00）凑到 ¥66，用「满 60 减 15」+ 9.9 券 | **¥32.40** | **¥28.60** |
| C 拆单 | 拆成两笔分别用券 | ¥34.20 | ¥26.80 |

**推荐方案 B**：多买一个甜筒，反而比 A 便宜 ¥2.70。

---

**你**：就按 B 来，下单吧

**拼单官**：

下单前最后核对一遍：

- 门店：珠江新城店（到店自取）
- 商品：板烧鸡腿堡 ×1、麦辣鸡腿堡 ×2、中薯 ×2、麦乐鸡 5 块 ×1、中杯冰美式 ×2、原味甜筒 ×1
- 原价 **¥66.00** → 券后 **¥32.40**（省 ¥33.60）
- 取餐方式：到店自取，无需配送费

确认无误请回复「确认下单」。

**你**：确认下单

<details><summary>中间调用</summary>

`⟨calculate-price⟩` → 复核金额一致
`⟨create-order⟩` → 订单创建成功，返回支付链接
`⟨query-order⟩` → 核对订单状态

</details>

✅ 订单已创建，订单号 `MCD-20261011-****`。
支付链接：`https://……`（请在链接内或麦当劳 App 完成支付，我不代付）

成员              原价    占比      应付     共省
-------------------------------------------------
小美            ¥14.00   23.0%     ¥7.44    ¥6.56

## 场景二 · 换个分摊口径

**你**：大家点的都差不多，改成优惠按人头均摊吧

**拼单官**：好，同样一单，换成按人头均摊：

```bash
python scripts/split_bill.py --total 32.40 \
  --goods-strategy even_discount \
  -m 小美:14.00 -m 阿强:16.00 -m 老王:19.00 -m 我:12.00
```

```
成员              原价    占比      应付     共省
-------------------------------------------------
小美            ¥14.00   23.0%     ¥6.85    ¥7.15
阿强            ¥16.00   26.2%     ¥8.85    ¥7.15
老王            ¥19.00   31.1%    ¥11.85    ¥7.15
我              ¥12.00   19.7%     ¥4.85    ¥7.15
-------------------------------------------------
合计            ¥61.00  100.0%    ¥32.40   ¥28.60
```

每人省的钱完全一样（¥7.15）。两种口径账单加总都是 ¥32.40，不会因为换口径就对不上账。

## 场景三 · 外卖场景（含配送费）

**你**：这次叫外卖，配送费 3 块，我发起人就不占大家便宜了，邮费我自己出

**拼单官**：明白，配送费由发起人承担，商品优惠仍按原价比例分摊：

```bash
python scripts/split_bill.py --total 35.40 --delivery 3.00 \
  --delivery-strategy initiator \
  -m 小美:14.00 -m 阿强:16.00 -m 老王:19.00
```

```
🍟 麦门拼单官 · 分账账单
订单实付 ¥35.40（商品 ¥32.40 + 配送费 ¥3.00）
分摊方式：商品优惠按原价比例分摊 · 配送费由发起人承担

成员              原价    占比      应付     共省
-------------------------------------------------
小美（发起人）   ¥14.00   28.6%    ¥12.26    ¥1.74
阿强            ¥16.00   32.7%    ¥10.58    ¥5.42
老王            ¥19.00   38.8%    ¥12.56    ¥6.44
-------------------------------------------------
合计            ¥49.00  100.0%    ¥35.40   ¥13.60

核对：各人应付加总 = ¥35.40，与订单实付一致 ✓
```

发起人自己承担了 ¥3.00 邮费，其余三人按比例分担商品实付。

> 若配送费改为按人头均摊，用 `--delivery-strategy even`（默认）即可。

## 场景四 · 有人临时不点了

**你**：老王改主意了，他那个 19 块的不点了

**拼单官**：明白，从账单里去掉老王并重新试算——去掉后订单降到满减门槛以下，
原来的「满 60 减 15」用不了了，改用 3 张 9.9 券，实付变成 ¥26.90。

```bash
python scripts/split_bill.py --total 26.90 -m 小美:14.00 -m 阿强:16.00
```

```
成员              原价    占比      应付     共省
-------------------------------------------------
小美            ¥14.00   46.7%    ¥12.55    ¥1.45
阿强            ¥16.00   53.3%    ¥14.35    ¥1.65
-------------------------------------------------
合计            ¥30.00  100.0%    ¥26.90    ¥3.10
```

券的适用性会随订单变化而变，所以每次改清单都要重新 `calculate-price`，不能沿用上一次的结论。

## 常见追问

**Q：为什么不用 AI 直接算分账？**
A：大模型做多步金额整除时经常差几分钱，且错误很隐蔽。分账涉及真金白银，
本项目用可测试的整数算法算，`tests/` 里有守恒性压测。

**Q：账单加总会不会对不上订单实付？**
A：不会。算法保证各人应付之和恒等于实付，脚本每生成一次账单都会自动核对并打印 `✓`。

**Q：可以按人头平分吗？**
A：可以。`--goods-strategy even_discount` 会把优惠按人头均摊，每人省同样的钱。

**Q：没有 Token 能用吗？**
A：分账是纯本地计算，`python scripts/split_bill.py` 不依赖任何 MCP 调用，
只要知道各人的原价和订单实付，随时可以算。
