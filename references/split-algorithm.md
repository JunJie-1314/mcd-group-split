# 分账算法说明

## 一、要解决什么

拼单用券之后，订单实付 `T` 小于大家选品的原价合计 `P`。
差额 `D = P − T` 就是这一单省下来的钱。

**问题**：这 `D` 该怎么分摊？每人实际该转发起人多少钱？

看似简单，实际有两个硬约束：

1. **守恒**：各人应付之和必须**精确等于** `T`。差 1 分钱，账单就对不上，群里一定有人发现。
2. **可解释**：分摊规则要能一句话说明白，否则点得多的人不服。

## 二、为什么必须用脚本，不能让大模型口算

语言模型做多步金额加减、带零头的按比例整除时，**错误率高且极其隐蔽**。
典型错误：

- 三人按比例分摊 `¥29.70`，模型可能给出 `¥8.49 / ¥9.71 / ¥11.50`，加起来是 `¥29.70`——
  看起来对，但每一项都和正确值差 1 分，是「凑出来的」而非「算出来的」。
- 更糟的是有时候加总不等于 `T`，出现 `¥0.01` 的缺口，而模型不会自己发现。

分账结果直接决定同事之间谁转谁多少钱，因此：

> **分摊逻辑全部使用确定性整数运算，并用单元测试锁定行为。大模型只负责调用脚本、讲解结果。**

## 三、三种商品分摊口径

记第 `i` 个人的原价小计为 `pᵢ`，`P = Σpᵢ`；订单商品部分的实付为 `G = T − 配送费`。

### 口径 A · 按原价比例分摊（`proportional`，默认）

```
应付ᵢ = G × pᵢ / P
```

点得多的人省得多，比例一致。**最不容易有争议**，因为每个人的折扣率相同。

### 口径 B · 优惠按人头均摊（`even_discount`）

```
优惠ᵢ = D_商品 / n
应付ᵢ = pᵢ − 优惠ᵢ
```

不管点多少，每人省的绝对值一样。适合大家点得差不多、图省事的场景。
注意：如果某人的原价小于其分摊到的优惠，会把他的应付**封顶到 0**（不能倒找钱），
脚本随后用最大余数法把差额补到其他人头上，保证仍然守恒。

## 四、配送费单独处理

配送费不参与「商品折扣」的比例计算，因为它和点了什么无关。三种口径：

| 口径 | 含义 | 适用 |
|---|---|---|
| `even`（默认） | 按人头均摊 | 最常见的公平做法 |
| `initiator` | 由发起人（第 1 位成员）承担 | 发起人为了凑单主动贴的邮费 |
| `proportional` | 按原价比例分摊 | 点得多的人也承担更多运费 |

## 五、零头怎么处理：最大余数法

按比例分摊经常除不尽。例如 `100 分` 由 3 人等分，每人 `33.33…`。

最朴素的做法是各自四舍五入，但那样**加总就会漂移**。
本实现采用**最大余数法**（Hamilton 法）：

1. 先向下取整，得到每人的基础值 `⌊100 × wᵢ / W⌋`；
2. 向下取整会剩一个零头 `missing`；
3. 把零头按「各自除不尽的余数」从大到小，每人补 1 分，直到分完。

这样既最大程度贴近比例，又保证**加总严格等于目标金额**。
余数并列时按成员的原始顺序补，保证同样输入永远得到同样输出（可复现、可审计）。

实现见 `scripts/split_bill.py` 的 `allocate()`，全程整数运算，不出现浮点。

## 六、边界情况

| 情况 | 处理 |
|---|---|
| 有人什么都没点（`pᵢ = 0`） | 权重为 0，承担 0 元商品费；配送费均摊时仍按人头占一份 |
| 所有人都没点 | 权重全 0，退化为按人头均分 |
| 只有一个成员 | 承担全部实付 |
| 没有任何优惠（`T = P`） | 应付等于原价，账单退化为恒等式 |
| `delivery_fee > total_paid` | 抛出 `ValueError` |
| 优惠大到把某人原价打穿 | 该人应付封顶 0，差额用最大余数法补给其他人 |

## 七、示例推演（仓库默认用例）

场景：三张 `¥9.9` 券，原价 `¥14.00 + ¥16.00 + ¥19.00 = ¥49.00`，实付 `¥29.70`，省 `¥19.30`。

按原价比例分摊（金额以分为单位：`p = [1400, 1600, 1900]`，`G = 2970`）：

| 人 | `G × pᵢ / P` | 向下取整 | 除不尽余数 | 补零头后 |
|---|---:|---:|---:|---:|
| 小美 | 848.57 | 848 | 2800 | **848**（8.48） |
| 阿强 | 969.79 | 969 | 3900 | **970**（9.70） |
| 老王 | 1151.63 | 1151 | 3100 | **1152**（11.52） |
| 合计 | 2970.00 | 2968 | — | **2970** ✓ |

零头 2 分补给了除不尽余数最大的阿强（3900）和老王（3100）。
各人应付加总 `848 + 970 + 1152 = 2970`，与订单实付完全一致。

命令：

```bash
python scripts/split_bill.py --total 29.70 \
  -m 小美:14.00 -m 阿强:16.00 -m 老王:19.00
```
